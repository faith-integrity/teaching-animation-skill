# 合并与交付

## 版本与装配

使用交付清单明确每个 Shot 的源码版本、样式版本、字幕/声音指纹、审核状态及媒体路径。部分镜头通过不代表全片已批准。合并前保留可复现的旧基线：源码、规格、时间轴、参数和对应音频，不能只留一个 MP4。

有连续主体的相邻镜头优先由共享场景重新渲染联合段；独立镜头可装配视频。拼接前检查分辨率、帧率、像素格式、编码、音频采样率、声道和时间基。流复制需要兼容参数；不能仅凭扩展名相同就 `-c copy`。需要时统一转码。参见 [FFmpeg 文档](https://ffmpeg.org/ffmpeg.html)。

封面可以静音显示，但保持图像比例；用户要求的裁剪和黑边规则写入规格。封面添加后更新全片时间码、外部 SRT/VTT 和 QA 抽查位置。

## 分层验收

1. **数据**：字幕文本版本、cue 顺序、音频文件和时长；运行时间轴校验。
2. **画面**：代表性关键帧、最长字幕、复杂公式、关键运动中间态、数量/方向/拓扑。
3. **声音**：每个新生成 cue 的内容与首尾音节、术语、停顿、拼接和音色；ASR 仅辅助。
4. **装配**：从最终 MP4 抽取 cue 中点及镜头交界前后画面；所有关键动作抽查，不仅检查独立预览。
5. **容器**：FFprobe 读取时长、视频参数、预期音轨；FFmpeg 完整解码。无声版本没有音轨可以合法，配音版本必须有有效音轨。

```bash
ffprobe -v error -show_streams -show_format -of json final.mp4
ffmpeg -v error -i final.mp4 -f null -
```

容器与计划时长比较时考虑一帧量化及音频编码延迟，容差写入 QA；不能用很大容差掩盖累计漂移。自动检查通过、模型已视觉检查、操作者主观批准分别记录。无法播放/试听时明确未验证的项目，不能写“无问题”。

## 工程交付

按需求提供成片、镜头审核版、字幕、源码、有效规格、分镜、依赖版本、渲染入口、时间轴、QA 与素材清单。一个明确的“当前交付”入口指向实际版本，旧版标为 superseded。给出文件大小/哈希可方便防止拿错文件。

公开工程排除个人路径、密钥、录音原件、未获分发许可的音色权重、字体、教材截图与大缓存。只公布可重建它们的说明和配置示例。用户手改参考源保留，不由生成脚本覆盖。用户要求发布时再确定目标仓库和账户；准备本地开源包不等于已经发布。
